# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Cinehub V2 is an AI "movie sommelier" (French UI, dark theme, blue accent) built with Next.js 16 (App Router), Tailwind CSS 4, Framer Motion and lucide-react. The user describes what they want to watch in free text; Gemini (Vercel AI SDK) proposes up to 10 films or series (5 shown, "Voir plus" reveals the next 5) (anime included), which are enriched with TMDB data (poster, rating, free streaming providers in France). The original V1 (static OMDb page) lives in `legacy/` and is not part of the app; its `js/key.js` holds an OMDb key that is in git history.

The product specs are in [cinehub_v2_sp_cifications_et_master_prompt.md](cinehub_v2_sp_cifications_et_master_prompt.md) (catalogue, done) and [cinehub_v3.md](cinehub_v3.md) (AI sommelier, current).

## Commands

Package manager is **pnpm** (pinned in `packageManager`).

- `pnpm dev`: dev server. `pnpm build` / `pnpm start`: production build and server.
- `pnpm lint` (ESLint; also scans `legacy/`, where one unused-var warning is expected), `pnpm exec tsc --noEmit` for types. There is no test suite.
- Route types (`PageProps<"/movie/[id]">`, `LayoutProps`) are generated by `next dev`/`next build`; run a build if `tsc` complains about them.
- Docker: no key is needed at build time; the keys are passed at run time.
  ```
  docker build -t cinehub .
  docker run -p 3000:3000 --env-file .env.local cinehub
  ```

`AGENTS.md` warns that this Next.js version has breaking changes; read the relevant guide in `node_modules/next/dist/docs/` before using Next APIs.

## Environment

`.env.local` (git-ignored) must define `TMDB_ACCESS_TOKEN` (the TMDB "API Read Access Token", sent as a Bearer header), `TMDB_BASE_URL` (`https://api.themoviedb.org/3`), `TMDB_IMAGE_BASE_URL` (`https://image.tmdb.org/t/p`), `GOOGLE_GENERATIVE_AI_API_KEY` (Gemini) and optionally `AI_MODEL` (default `gemini-3.5-flash-lite`). All TMDB and Gemini calls are server-side; no key may reach client code.

## Architecture

- [lib/tmdb.ts](lib/tmdb.ts) is the only TMDB client. `tmdbFetch` adds the Bearer header and `language=fr-FR` and throws `TmdbError` (with `status`). Cache Components is enabled (`next.config.ts`), so the data functions (`getTrendingMovies`, `getMovieDetails`, `getMovieVideos`, `getGenreMap`) use `"use cache"` + `cacheLife`, while `searchMovies` is deliberately uncached. `getMovieDetails` appends `credits` for the cast; `getMovieVideos` falls back to en-US and keeps YouTube only. List endpoints return `genre_ids` only, hence `getGenreMap`.
- AI flow: `HeroSearch` (client, home page) calls the Server Action `generateRecommendations` in [app/actions.ts](app/actions.ts). It validates the prompt (5-500 chars), asks Gemini through `generateText` + `Output.object` (zod schema: type, titre, titre_original, annee, raison_du_choix; up to 10 items; type film|serie), then for each item calls `findMedia` (TMDB `movie` or `tv` search by type; searches the original title first, then the French one; ignores TMDB entries with < 10 votes, which are false positives) and `getWatchProviders(id, type)` (region FR; free and ads providers become `freeProviders`, flatrate ones become `subscriptionProviders` (Netflix, Prime Video…)). It returns `{ ok, recommendations } | { ok: false, error }`; failures are logged with `console.error` and never thrown to the client. Model choice matters for latency: `gemini-3.8-flash` took 50-100 s, `gemini-3.5-flash-lite` about 8 s, and `thinkingLevel` is set to `low` (`minimal` is rejected by some models).
- TMDB only exposes one JustWatch page link per film and region, not a link per platform: `RecommendationCard`'s "Regarder gratuitement" button opens that page, with the provider logos next to it. Series have no internal details page: title and poster link to the TMDB page. Only the providers reported by TMDB are shown; piracy/unauthorized streaming sites and Telegram channels are deliberately never linked. The card also lists subscription platforms under "Avec abonnement". Without free providers it shows "Non disponible gratuitement pour le moment".
- Pages: `app/page.tsx` is just `HeroSearch` (static). `app/movie/[id]/page.tsx` reads `params` inside a `<Suspense>` child (required by Cache Components) and calls `notFound()` on invalid ids or TMDB 404; because of streaming, that 404 page is served with HTTP 200. `hero.tsx`, `movie-grid.tsx` and `movie-card.tsx` are leftovers of the V2 catalogue home and are currently unused.
- Search: `SearchLauncher` (in the fixed `Navbar`, owns the Ctrl/Cmd+K shortcut) opens `CommandPalette`, which debounces 300 ms, aborts stale requests and calls `app/api/search/route.ts`; that route returns trimmed results (id, title, year, w92 poster).
- Trailer: `TrailerButton` opens a modal with a `youtube-nocookie.com` iframe.
- Server Components by default; only components that need state/animation are `"use client"` (`HeroSearch`, `FadeIn`, `SearchLauncher`, `CommandPalette`, `TrailerButton`). Images go through `next/image`, allowed by `images.remotePatterns` for `image.tmdb.org/t/p/**`.

## Deployment

`next.config.ts` sets `output: "standalone"`. Server Actions, the API route and `"use cache"` need a Node server, so static export and Nginx are not possible: the multi-stage [Dockerfile](Dockerfile) runs `node server.js` on port 3000. The home page is static and the build makes no external call, so the build needs no secret; `TMDB_ACCESS_TOKEN`, `GOOGLE_GENERATIVE_AI_API_KEY` (and optionally `AI_MODEL`) must be passed as environment variables at run time. `.dockerignore` excludes `.env*` and `legacy/`.
