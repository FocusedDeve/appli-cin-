# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Cinehub V2: a movie catalogue (French UI, dark theme, blue accent) built with Next.js 16 (App Router), Tailwind CSS 4, Framer Motion and lucide-react, using the TMDB API. The original V1 (static OMDb page) lives in `legacy/` and is not part of the app; its `js/key.js` holds an OMDb key that is in git history.

The product spec is in [cinehub_v2_sp_cifications_et_master_prompt.md](cinehub_v2_sp_cifications_et_master_prompt.md).

## Commands

Package manager is **pnpm** (pinned in `packageManager`).

- `pnpm dev`: dev server. `pnpm build` / `pnpm start`: production build and server.
- `pnpm lint` (ESLint; also scans `legacy/`, where one unused-var warning is expected), `pnpm exec tsc --noEmit` for types. There is no test suite.
- Route types (`PageProps<"/movie/[id]">`, `LayoutProps`) are generated by `next dev`/`next build`; run a build if `tsc` complains about them.
- Docker: the image needs the TMDB token both at build and at run time (see below).
  ```
  docker build --secret id=tmdb_token,src=token.txt -t cinehub .
  docker run -p 3000:3000 -e TMDB_ACCESS_TOKEN=... cinehub
  ```

`AGENTS.md` warns that this Next.js version has breaking changes; read the relevant guide in `node_modules/next/dist/docs/` before using Next APIs.

## Environment

`.env.local` (git-ignored) must define `TMDB_ACCESS_TOKEN` (the TMDB "API Read Access Token", sent as a Bearer header), `TMDB_BASE_URL` (`https://api.themoviedb.org/3`) and `TMDB_IMAGE_BASE_URL` (`https://image.tmdb.org/t/p`). All TMDB calls are server-side; the token must never reach client code, which is why the client searches through `/api/search`.

## Architecture

- [lib/tmdb.ts](lib/tmdb.ts) is the only TMDB client. `tmdbFetch` adds the Bearer header and `language=fr-FR` and throws `TmdbError` (with `status`). Cache Components is enabled (`next.config.ts`), so the data functions (`getTrendingMovies`, `getMovieDetails`, `getMovieVideos`, `getGenreMap`) use `"use cache"` + `cacheLife`, while `searchMovies` is deliberately uncached. `getMovieDetails` appends `credits` for the cast; `getMovieVideos` falls back to en-US and keeps YouTube only. List endpoints return `genre_ids` only, hence `getGenreMap`.
- Pages: `app/page.tsx` renders `Hero` (trending #1) and a Bento `MovieGrid` of the rest (every 7th tile spans 2x2). `app/movie/[id]/page.tsx` reads `params` inside a `<Suspense>` child (required by Cache Components) and calls `notFound()` on invalid ids or TMDB 404; because of streaming, that 404 page is served with HTTP 200.
- Search: `SearchLauncher` (in the fixed `Navbar`, owns the Ctrl/Cmd+K shortcut) opens `CommandPalette`, which debounces 300 ms, aborts stale requests and calls `app/api/search/route.ts`; that route returns trimmed results (id, title, year, w92 poster).
- Trailer: `TrailerButton` opens a modal with a `youtube-nocookie.com` iframe.
- Server Components by default; only components that need state/animation are `"use client"` (`FadeIn`, `SearchLauncher`, `CommandPalette`, `TrailerButton`). Images go through `next/image`, allowed by `images.remotePatterns` for `image.tmdb.org/t/p/**`.

## Deployment

`next.config.ts` sets `output: "standalone"`. Static export is not possible (API route, dynamic route, `"use cache"`), so Nginx is not used: the multi-stage [Dockerfile](Dockerfile) runs `node server.js` on port 3000. The home page is prerendered during `pnpm build` and therefore calls TMDB, so the Dockerfile takes the token as a BuildKit secret (`tmdb_token`) for the build; at run time `TMDB_ACCESS_TOKEN` must be passed as an environment variable. `.dockerignore` excludes `.env*` and `legacy/`.
